### 任务描述

给定一段非结构化的健身训练文本，根据以下规则解析其中的训练动作，并输出严格合法的 JSON。

---

## 1. 动作名称映射

将文本中的动作名称映射为标准枚举值：

- 出现“卧推”、“平板卧推”、“Bench Press” → `BENCH_PRESS`
- 出现“上斜”、“上胸” → `INCLINE_PRESS`
- 出现“深蹲”、“蹲腿”、“Squat” → `SQUAT`
- 出现“硬拉”、“拉背”、“Deadlift” → `DEADLIFT`
- 出现“推举”、“肩推” → `OHP`
- 其他未匹配动作 → `OTHER`

动作匹配不区分英文大小写。

若一句话中包含多个动作，必须按照动作出现顺序分别生成记录。

---

## 2. 重量归一化

所有重量最终统一输出为 **kg**，字段为 `final_weight`。

### 2.1 已给出总重量

如果文本直接给出总重量，例如：

- `卧推80kg`
- `深蹲100kg`

则直接使用该重量，不再额外增加杆重。

例如：

`卧推80kg` → `80.0`

---

### 2.2 磅转换为千克

若重量单位为 `lbs`、`lb` 或“磅”，则：

`kg = lbs ÷ 2.2`

例如：

`卧推220lbs` → `100.0kg`

计算结果为浮点数。

---

### 2.3 单边重量

若文本出现以下含义：

- `一边20kg`
- `每边20kg`
- `单边20kg`
- `一边20`
- `每边20`

则该数字表示**单边杠铃片重量**，总重量计算公式为：

`final_weight = 单边重量 × 2 + 杆重`

如果单边重量没有明确写单位，例如“每边25”，默认单位为 `kg`。

不同动作使用的杆重如下：

| 动作            | 杆重 |
| --------------- | ---: |
| `SQUAT`         | 25kg |
| `DEADLIFT`      | 25kg |
| `BENCH_PRESS`   | 15kg |
| `OHP`           | 15kg |
| `INCLINE_PRESS` | 15kg |
| `OTHER`         |  0kg |

例如：

`硬拉一边25kg`
→ `25 × 2 + 25 = 75kg`

`卧推每边25`
→ `25 × 2 + 15 = 65kg`

只有明确出现“一边 / 每边 / 单边”等语义时才增加杆重。

如果文本已经给出总重量，则绝不能再次增加杆重。

---

## 3. 训练次数、组数和练习模式

`exercise_mode` 只能取以下三个枚举：

- `STANDARD`
- `REST_PAUSE`
- `CLUSTER`

按照以下规则判断。

### 3.1 STANDARD

若采用普通的“组数 × 次数”形式，例如：

- `5x5`
- `5×5`
- `3x10`

则：

- `sets` = 前一个数字
- `reps` = 后一个数字
- `exercise_mode` = `STANDARD`

例如：

`卧推80kg 5x5`

解析为：

```json
{
  "sets": 5,
  "reps": 5,
  "exercise_mode": "STANDARD"
}
```

---

### 3.2 REST_PAUSE

若次数之间使用 `+` 连接，例如：

- `10+5+3`
- `8+4`
- `12+3+2`

则视为一次 Rest-Pause 训练：

- `sets` = 1
- `reps` = 所有数字之和
- `exercise_mode` = `REST_PAUSE`

例如：

`10+5+3`

计算：

`10 + 5 + 3 = 18`

结果：

```json
{
  "sets": 1,
  "reps": 18,
  "exercise_mode": "REST_PAUSE"
}
```

---

### 3.3 CLUSTER

若次数之间使用逗号连接，例如：

- `2,2,2,2,2`
- `5,5,5`
- `3,3,3,3`

则：

- `sets` = 逗号分隔出的数字数量
- 如果所有数字相同，`reps` = 每组次数
- `exercise_mode` = `CLUSTER`

例如：

`2,2,2,2,2`

结果：

```json
{
  "sets": 5,
  "reps": 2,
  "exercise_mode": "CLUSTER"
}
```

对于规则输入，可以默认逗号分隔的每组次数相同。

---

## 4. 多动作处理与数据继承

如果文本包含多个动作，必须分别生成多条记录。

例如：

`硬拉一边25kg 5,5,5；卧推每边25`

其中第二个动作只明确给出了动作和重量，没有再次写组数、次数和练习模式。

此时应继承**紧邻的上一个动作**的：

- `sets`
- `reps`
- `exercise_mode`

但以下字段不得继承：

- `action`
- `final_weight`

因此：

`硬拉一边25kg 5,5,5；卧推每边25`

解析为：

```json
{
  "entries": [
    {
      "action": "DEADLIFT",
      "final_weight": 75.0,
      "sets": 3,
      "reps": 5,
      "exercise_mode": "CLUSTER"
    },
    {
      "action": "BENCH_PRESS",
      "final_weight": 65.0,
      "sets": 3,
      "reps": 5,
      "exercise_mode": "CLUSTER"
    }
  ]
}
```

仅当当前动作没有明确给出训练组次信息时才继承上一动作的数据。

如果当前动作明确给出了新的组次信息，则必须使用当前动作自己的数据。

---

## 5. 判定优先级

对于单个动作，按以下顺序解析：

1. 识别动作名称并映射 `action`
2. 判断重量是总重量还是单边重量
3. 必要时执行 lbs → kg 转换
4. 必要时根据动作加入杆重
5. 根据训练表达式判断模式：
   - 出现 `+` → `REST_PAUSE`
   - 出现 `,` → `CLUSTER`
   - 出现 `x` 或 `×` → `STANDARD`

6. 若当前动作没有组次信息，则继承上一动作的 `sets`、`reps` 和 `exercise_mode`

---

## 6. 输出格式

只能输出严格合法的 JSON，不要输出 Markdown，不要解释计算过程，不要添加任何额外文本。

格式：

```json
{
  "entries": [
    {
      "action": "ENUM",
      "final_weight": 0.0,
      "sets": 0,
      "reps": 0,
      "exercise_mode": "STANDARD"
    }
  ]
}
```

字段要求：

- `action`：只能为
  `BENCH_PRESS`、`INCLINE_PRESS`、`SQUAT`、`DEADLIFT`、`OHP`、`OTHER`
- `final_weight`：浮点数，单位 kg
- `sets`：整数
- `reps`：整数
- `exercise_mode`：只能为
  `STANDARD`、`REST_PAUSE`、`CLUSTER`

不得添加未定义字段。
